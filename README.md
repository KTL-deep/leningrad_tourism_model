# 🗺️ Leningrad Tourism Model

Пайплайн для формирования **Универсальной информационной модели города (UCM)** и генерации слоя городских блоков Ленинградской области. Реализует первый шаг алгоритма оценки туристического потенциала территорий.

---

## 📋 Что делает этот проект

1. **Загружает пространственные данные** из OpenStreetMap через `osmnx`: границы, дороги, водные объекты, землепользование, сервисы и здания.
2. **Загружает экспертные данные** из локальных файлов: объекты культурного наследия (ОКН), особо охраняемые природные территории (ООПТ), цифровая модель рельефа (DEM).
3. **Нарезает территорию на городские блоки** — дискретные полигональные ячейки — используя дороги и реки как физические барьеры (библиотека `blocksnet`).
4. **Атрибутирует блоки** через пространственные соединения (Spatial Join): считает количество ОКН и сервисов, определяет доминирующий тип землепользования.
5. **Экспортирует результаты** в GeoJSON для дальнейшего анализа в QGIS:
   - `data/processed/ucm_blocks.geojson` — итоговый слой блоков (UCM)
   - `data/processed/osm/*.geojson` — базовые слои OSM (граница, дороги, вода, landuse, amenities/buildings)

## 🚀 Быстрый старт

### 1. Клонировать и настроить окружение

```bash
git clone <url>
cd leningrad_tourism_model

# Создать виртуальное окружение (PyCharm делает это автоматически)
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux / macOS
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

> ⚠️ **Windows**: `geopandas` и `osmnx` требуют скомпилированных C-расширений. Убедитесь, что вы используете **Python 3.11 или 3.12**. Для проблемных установок используйте Conda:
> ```bash
> conda install -c conda-forge geopandas osmnx
> ```

### 3. Подготовить данные (опционально)

Поместите региональные данные в папку `data/raw/`:
- `okn.geojson` — точки ОКН в формате GeoJSON
- `oopt.geojson` — полигоны ООПТ в формате GeoJSON
- `dem.tif` — растровый файл ЦМР

Если файлы отсутствуют, пайплайн продолжит работу с пустыми слоями для этих данных.

### 4. Запустить пайплайн

```bash
.\.venv\Scripts\python.exe main.py
```

По умолчанию пайплайн запускается для населённого пункта **Рощино, Ленинградская область**.  
Чтобы изменить регион, отредактируйте строку в `main.py`:

```python
test_region = "Гатчина, Ленинградская область, Россия"
generate_ucm(region_name=test_region)
```

### 5. Посмотреть результат

Откройте в **QGIS**:
- `data/processed/ucm_blocks.geojson` — слой городских блоков с атрибутами
- `data/processed/osm/*.geojson` — базовые слои OSM (для контроля исходных данных)

## ⚙️ Зависимости

| Библиотека | Назначение |
|---|---|
| `blocksnet` | Пространственная кластеризация → городские блоки |
| `osmnx` | Получение данных OpenStreetMap |
| `geopandas` | Работа с геопространственными данными |
| `shapely` | Геометрические операции |
| `pandas` | Табличные данные |
| `pandera` | Валидация схемы данных (используется внутри blocksnet) |
| `requests` | HTTP-запросы |
| `beautifulsoup4` | HTML-парсинг (реестры ОКН) |

## 🔧 Известные особенности

- **Хотфикс pandera**: библиотека `blocksnet` использует `pandera` для внутренней валидации данных, что конфликтует с новыми версиями `geopandas`. В `blocks_generator.py` применён monkey-patch, который отключает эту валидацию. Это временное решение, которое следует обновить при выходе совместимых версий `blocksnet`.
- **Время выполнения**: загрузка данных OSM и нарезка блоков для крупных регионов может занимать **5–20 минут** в зависимости от производительности компьютера и скорости интернета.
- **Кэш osmnx**: повторные запросы к OSM кэшируются локально (папка `cache/`, исключена из git).
- **Кодировка Windows**: вывод пайплайна настроен на UTF-8, чтобы кириллица не ломала запуск при редиректе/логировании.

## 🗺️ Контекст проекта

Данный репозиторий реализует **Шаг 1** более широкого алгоритма оценки туристического потенциала Ленинградской области:

```
Шаг 1 (этот репозиторий): Генерация UCM и слоя городских блоков
   ↓
Шаг 2: Расчёт показателей туристической привлекательности для каждого блока
   ↓
Шаг 3: Оптимизация маршрутов и точек притяжения (граф доступности)
   ↓
Шаг 4: Визуализация и отчётность
```
