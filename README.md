# 🗺️ Leningrad Tourism Model (Предиктивная модель мастер-планирования)

![Python Version](https://img.shields.io/badge/python-3.10%2B-blue)
![BlocksNet](https://img.shields.io/badge/powered%20by-BlocksNet-orange)
![Streamlit](https://img.shields.io/badge/UI-Streamlit-red)
![License](https://img.shields.io/badge/license-MIT-green)

**Leningrad Tourism Model** — это интерактивная предиктивная параметрическая модель полифункционального городского и регионального развития. Это система поддержки принятия решений (DSS), которая алгоритмически предписывает оптимальные типы землепользования (Target Land Use) для развития туристического и инфраструктурного потенциала территорий.

Система разработана на основе передовых методов **мульти-критериального пространственного анализа (MCE/AHP)**, топологической генерации городской ткани с помощью **диаграмм Вороного** и стохастического разрешения конфликтов с использованием алгоритма **имитации отжига (Simulated Annealing)**.

---

## 🏗️ Архитектура и Пайплайн

Вычислительное ядро построено на базе библиотеки пространственного анализа [BlocksNet](https://github.com/iduprojects/blocksnet). Весь конвейер (Pipeline) автоматизирован и состоит из 5 основных шагов:

### 1. Топологическая генерация (Пространственная дискретизация)
Пространство (на основе данных OpenStreetMap) алгоритмически "нарезается" на компактные городские блоки (UCM — Urban Context Models). Границами блоков выступают строгие физические барьеры среды: автомобильные дороги, железнодорожные магистрали и реки.

### 2. Семантическая экстракция (UCM Builder)
Каждый сгенерированный топологический блок обогащается семантикой. Алгоритм проводит пространственное соединение (Spatial Join) с различными слоями ГИС-данных:
* Объекты Культурного Наследия (ОКН)
* Особо Охраняемые Природные Территории (ООПТ)
* Лесные и парковые массивы
* Объекты туризма, питания и социальной инфраструктуры (OSM POI)

Также на этом этапе с использованием графов (NetworkX) строится **матрица транспортной доступности** между всеми блоками.

### 3. Сценарное взвешивание (AHP + WLC)
Метод анализа иерархий Томаса Саати (AHP) в связке с Weighted Linear Combination (WLC) используется для расчета агрегированных индексов пригодности ($S_{ik}$) каждого блока под конкретные функции:
* 🌲 Парк / Рекреация
* 🏠 Жилая застройка
* 🏪 Коммерция / Услуги
* 🚉 Инфраструктурный Хаб

Расчет производится **мультисценарно**: веса пересчитываются для сценариев *«Экоцентризм»*, *«Историко-центризм»* и *«Инфраструктурный»*.

### 4. Глобальная оптимизация (Simulated Annealing)
Разрешение пространственных конфликтов. Алгоритм имитации отжига (Simulated Annealing) назначает каждому блоку идеальный тип застройки (`Target Land Use`). 
Целевая функция максимизирует индекс пригодности ($S_{ik}$) и одновременно учитывает **пространственную синергию** (например, жилую застройку алгоритм старается размещать ближе к паркам и инфраструктурным хабам). 
Также на этом этапе рассчитывается параметр `Capacity` — ожидаемая обслуживающая ёмкость территории (чел).

### 5. Интерактивный UI Дашборд
Слой `Streamlit` + `Folium` предоставляет интуитивно понятный картографический веб-интерфейс для стейкхолдеров. Пользователь может на лету переключать сценарии развития, визуально оценивать предписанную модель землепользования и изучать аналитику по каждому блоку во всплывающих окнах.

## 📂 Структура проекта

```text
leningrad_tourism_model/
├── configs/
│   └── ahp_constants.json          # Весовые коэффициенты (AHP) для всех сценариев
├── data/
│   ├── raw/                        # Исходные файлы (ОКН, ООПТ и др.)
│   └── processed/                  # Сгенерированные геоданные, матрицы доступности
├── src/
│   ├── analysis/
│   │   ├── ahp.py                  # Логика метода анализа иерархий (AHP)
│   │   └── optimizer.py            # Алгоритм имитации отжига (Simulated Annealing)
│   ├── etl/
│   │   ├── gis_loader.py           # Парсеры локальных геоданных (GeoJSON/SHP)
│   │   └── osm_loader.py           # Адаптер к API OpenStreetMap (OSMnx)
│   └── generation/
│       ├── topological_generator.py# Нарезка полигонов по алгоритмам Вороного
│       └── ucm_builder.py          # Агрегация атрибутов (Spatial Join)
├── tests/                          # Модульные и интеграционные тесты (Pytest)
├── main.py                         # Главный скрипт бэкенда (выполнение Pipeline)
├── app.py                          # Frontend (Дашборд Streamlit)
├── DETAILED_PLAN.md                # История разработки (Roadmap)
└── requirements.txt                # Зависимости Python
```

## 🚀 Установка и запуск

### 1. Установка окружения
Рекомендуется использовать виртуальное окружение.
```bash
git clone <repository_url>
cd leningrad_tourism_model
python -m venv .venv
# Активация окружения (Windows):
.venv\Scripts\activate
# Активация окружения (Linux/Mac):
# source .venv/bin/activate

# Установка зависимостей (совместимо с Python 3.11 и 3.12)
pip install -r requirements.txt
```

### 2. Генерация данных (Запуск вычислений)
Для запуска расчетов (скачивание данных, генерация блоков, AHP и оптимизация) просто выполните:

```bash
python main.py
```
*⚠️ Процесс может занять длительное время (10-20 минут) в зависимости от размера выбранного региона и скорости интернета при скачивании дорожных графов OSM.*

### 3. Запуск веб-дашборда
Для визуализации результатов в браузере:
```bash
streamlit run app.py
```
После запуска в терминале появится локальный URL (обычно `http://localhost:8501`), который автоматически откроется в браузере.

## 🛠️ Конфигурация и тюнинг

Главный конфигурационный файл: `configs/ahp_constants.json`.
В нем вы можете редактировать:
- **`scenarios`**: Наборы сценариев (Экоцентризм, Историко-центризм, Инфраструктурный).
- Весовые коэффициенты для каждой связки "Сценарий" -> "Функция (Target Land Use)" -> "Атрибут (Лес, ОКН, Дороги)".
Изменив этот файл и перезапустив `main.py`, вы получите совершенно новую предиктивную модель зонирования территории.
