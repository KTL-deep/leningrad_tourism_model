# ADR 0007 — Проверяемая загрузка OSM-наблюдений, не готовая маршрутизация

Дата: 2026-10-19. Статус: принято для части E03. Уточняет черновой ADR 0006; прежние адаптеры сохранены, но не подключены к новому пути.

## Реализация

- Один комбинированный запрос Overpass загружает поддерживаемые POI и highway ways, затем все узлы/члены выбранных объектов. Это сокращает число обращений и позволяет сохранять единый исходный снимок для разных ролей.
- Явный bbox строится по analysis_geometry, если задана, иначе по request_geometry. Он содержит **все** части MultiPolygon, не соединяет кольца и не выбирает крупнейшую часть. Координаты сериализуются без округления внутрь. Bbox — область сбора, не доказанное расчётное окружение; попадание в административную геометрию хранится отдельно. Нет выдуманного буфера доступности.
- Технические ограничения: bbox до 1000 км² по геодезической площади, до 16 MiB ответа/200000 элементов, серверный timeout 25 с/maxsize 128 MiB, клиентские connect/read 10/45 с. Это опубликованные ограничения нагрузки, не методика экологической ёмкости. Большая территория отклоняется, а не незаметно упрощается.
- Overpass JSON принимается только с поддерживаемой схемой, временной меткой базы, без remark и с финальным счётчиком nodes/ways/relations/total, согласованным с фактическими уникальными ID. Допустим дополнительный areas=0; ненулевые area-элементы пока не поддерживаются. Обрыв/неполный ответ не превращается в успешный пустой набор. Пустой согласованный запрос — наблюдение источника, не доказательство физического отсутствия услуг.
- POI сохраняют type/id, категории и исходные теги. Узловая координата — наблюдение OSM; center way/relation обозначается как оценённый центр bbox, не вход/проверенная площадка. Без центра объект не выбрасывается, геометрия null и флаг качества. Мощность/публичная доступность остаются неизвестны, даже если сырые неоднозначные теги присутствуют.
- Дорожные линии сохраняют полные node refs, включая узлы за границей, без геометрического обрезания. Пересечение линий не создаёт искусственный узел. Геодезические длины WGS84 — метры, время движения не выводится. Направление raw-тега сохраняется с отдельным implicit_roundabout/unknown; оно не заменяет режимы доступа, поворотные/временные ограничения и правила для пешеходов. routing_ready=false, surrounding_adequacy=not_validated.
- Источник по умолчанию — документированный бесплатный Private.coffee Overpass: операторские условия прочитаны 19.10.2026. Endpoint меняется только явно, для нестандартного требуется подтверждение условий. TLS/идентификация/общий lock и интервал 1,1 с, не более двух попыток только при timeout/502/503/504 с паузой. HTTP 403/429/500 и ошибка валидации не запускают автоматическую серию повторов. Автоматического обхода серверов нет.
- Кэш привязан к endpoint, запросу, area_id и версии; при чтении проверяются источник/хэш/байты и весь парсинг. Ошибка не стирает прежний снимок/указатель. Подтверждённые аварийные lock не очищаются автоматически — известное ограничение восстановления E15, а не обещанная готовность оркестратора.
- CLI collect_osm связывает boundary, исходный снимок и производные GeoJSON-слои с RunManifest. Экспорт — независимая атомарная копия, не hard link на blob: редактирование в ГИС не должно портить архив. Изменённый пользователем экспорт не перезаписывается. Supporting-снимки проверяются по территории/байтам, но сами не включают расчётные возможности.
- Полный проверенный **ответ запроса** может дать входы наблюдательной карты, но не полноту реальных POI. Дорожные наблюдения явно исключаются из qualified network, пока не проверены окружение/режимы/ограничения. Нет спроса/мощности/прироста туристов/инвестиционных рекомендаций из числа POI.

## Реальная доступность и ограничения

19.10.2026 контрольные обращения дали Private.coffee 500 (GET и POST), основной Overpass 502/заполненная очередь, VK 504. Новый CLI для Гатчины в 13:10 UTC также получил 500: сохранён partial с прежней границей, ошибкой и исключёнными POI/network; числа объектов не подставлялись нулями, новых реальных слоёв POI/дорог нет. Положительный путь парсинга/кэша/экспорта проверен пока только синтетически. Это не готовность E03 или эмпирическая валидация туризма.

Следующий разрешённый путь при длительном сбое — реализация/проверка резервного источника OSM-выгрузок с контролем размера, условий и охвата либо повтор после восстановления сервиса. Не просить пользователя готовить CSV/PDF и не обходить защиту/лимиты. Режимы/окружение и маршруты остаются E07.
