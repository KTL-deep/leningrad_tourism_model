# ADR 0004 — Первый исполняемый путь контрактов и допуска входов

Дата: 2026-10-19. Статус: принято для ограниченного среза E02; реализуются решения ADR 0003. Не заменяет будущие адаптеры E03/E04.

## Границы шага

В `docs` по просьбе автора удалены три устаревших руководства: `ARCHITECTURE.md`, `PROJECT_GUIDE.md`, `DETAILED_PLAN_v3.md`. Вместо дублирующего описания оставлен навигационный README. Журнал, доказательства, библиография и история решений сохранены. «Начать заново» означает работать по v1.1, не сбрасывать пользовательские данные/код и не стирать результаты аудита.

## Решения реализации

1. Реализовать только первые нужные сущности: `SourceSnapshot`, числовой `Evidence` и `RunManifest`, schema_version=1. Все будущие сущности заранее не создавать. Неизвестное значение — `None` с причиной, не 0; числа конечны, единицы обязательны, derived/estimated требуют метода, оценка — интервала.
2. Использовать локальное файловое хранилище: исходные байты, JSON-метаданные снимков, свидетельства и манифесты. Идентичность снимка зависит от источника, территории, URL, SHA-256 байтов, версии парсера, типа и полноты, но не от времени повторной записи. Повтор сохраняет первый timestamp. Это ещё не история наблюдений/TTL из E05.
3. Не изменять опубликованный файл. Полная временная запись публикуется атомарной hard link без замены существующего пути; конфликт содержимого — ошибка. На неподдерживаемой файловой системе операция явно завершается ошибкой, не переходит к небезопасной перезаписи. Остаточные неподключённые объекты после прерывания не дают права удалять чужие данные.
4. Проверять на чтении версию схемы, идентичность метаданных и исходные байты по длине/хэшу. Проверять ссылки Evidence → snapshot → run и принадлежность территории. Это защита от ошибок/повреждения данных, не обещание защиты от владельца ОС, способного целиком подменить хранилище.
5. `source_policy` принимает **утверждения адаптера** о происхождении, доступе, покрытии, периоде, единицах и проверке содержимого. Она не делает эти проверки сама. По умолчанию всё не проверено; HTTP 200 не включает набор. Типы флагов строгие, территории не смешиваются, причины исключения сохраняются.
6. Для первого консервативного пути принимать только complete-наборы с выполненными условиями. Partial/unknown не повышаются до проверенного численного входа. Правила полезного отображения частичных пространственных слоёв будут уточняться вместе с E03/E04, не через молчаливую подмену полноты.
7. Возможности — **готовность входов**, а не уже вычисленные продукты: boundary+poi позволяют начать карту; network добавляет доступность; demand+service_capacity нужны для U. Статистика/отзывы не глобальные зависимости. Отзывы не заменяют D/K. Наличие legal_rules означает лишь вход для индивидуальной проверки, не разрешение мероприятия.
8. `prepare_inputs` связывает решения со снимками, сверяет источник/территорию/полноту и байты, сохраняет производный артефакт оценки входов и run manifest. Артефакт явно обозначен `derived_input_assessment`, не официальная статистика и не сырой ответ внешнего сервера. Он содержит допуски, исключения, исходные утверждения адаптеров и конфигурацию. Без необходимой базы статус failed, при неполноте partial. Никаких результатов о туризме функция не вычисляет.

## Проверка и остаток работ

Офлайн-тесты используют временные каталоги и явно синтетические утверждения/байты. Проверяются отсутствие статистики/отзывов без блокировки независимых входов, отсутствие D/K без выдуманного U, чужая территория/источник, повреждение данных, идемпотентность и цепочка происхождения. Фактические числа прогона — в журнале и validation, а не заранее в этом решении.

Ещё не реализованы StudyArea/геометрические контракты, адаптеры обнаружения/сбора по территории, содержательные валидаторы, полный оркестратор с возобновлением, сроки хранения по лицензии и работа с отзывами. Старые main.py/app.py не переключаются на новый путь до интеграции. E02 не объявляется завершённым только по наличию этих трёх контрактов.
