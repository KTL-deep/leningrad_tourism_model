# ADR 0009 — Нарезка baseline с закреплённым BlocksNet 1.x

Дата: 2026-10-23. Статус: принято; результаты проверок — в validation.

## Причина

Совместимый с GeoPandas 1.x upstream BlocksNet (`f576517e99c53e74beda29908548f58bfa758e4c`, установлен как 1.0.0a3.post14) больше не экспортирует старый `BlocksGenerator`. Установка зависимостей не устраняет несовместимость старого генератора проекта.

Проверен импорт новой высокоуровневой функции `blocksnet.blocks.cutting.processing.cut_urban_blocks`: он завершается `ModuleNotFoundError: torch`, потому что пакет безусловно импортирует ML-классификатор через processing/core → split → classification. Классификатор не нужен для текущей нарезки по дорогам/воде. Добавлять тяжёлый ML-стек только ради этой цепочки импортов не требуется.

## Решение

- Использовать `cut_blocks(boundaries_gdf, lines_gdf, polygons_gdf)` из файла `blocksnet/blocks/cutting/processing/cut.py` **установленного закреплённого пакета**. Этот модуль не имеет относительных импортов и зависит лишь от уже установленных GeoPandas/Pandas/NumPy/Shapely/loguru.
- Загружать только данный модуль через локальный адаптер, не выполняя `blocksnet.blocks.cutting.__init__`, который включает классификатор. Не создавать фиктивные модули, не подменять глобальные объекты библиотеки, не редактировать site-packages и не подменять алгоритм своим fallback.
- Поскольку низкоуровневый модуль не вызывает высокоуровневую проверку схем, адаптер обязан явно проверять типы, валидность/непустоту геометрии, назначенную метрическую проекцию и согласованность CRS. Не восстанавливать прежний monkeypatch `BlocksSchema = lambda x: x`.
- Объединять дороги/железные дороги/водные линии как линейные барьеры; водные Polygon/MultiPolygon передавать отдельно для вычитания площади. Не терять площади воды, отверстия границы и отдельные компоненты территории.
- Сохранить выходной контракт `TopologicalGenerator`: EPSG:4326, `block_id`, `dist_to_hubs`, `geometry`. Порог площади проверяется как конечное неотрицательное число; пустой результат не считается успешной генерацией.

## Границы и риски

Путь низкоуровневого файла — внутренний API конкретного pinned upstream. Обновление ревизии требует повторной проверки адаптера, а не автоматического перехода на новую ветку. Классификация/ML и старые алгоритмы Voronoi не включаются; используется фактическая нарезка по барьерам с polygonize. Сетевые загрузчики и прочая baseline-логика не становятся проверенными из-за исправления этого импорта.

Тесты должны вызывать настоящий установленный cutter на синтетических метрических геометриях, не только mock возвращаемого результата. Отдельно проверяются импорт без torch, линии/площади воды, отсутствие барьеров, multipart/отверстия, CRS/ошибки геометрии и фильтрация площади. Это не реальная валидация всего `main.py` или туристических рекомендаций.
