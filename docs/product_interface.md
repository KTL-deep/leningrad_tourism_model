# Продуктовый интерфейс

Уточнение автора от 02.11.2026: нужен интерфейс конечного продукта, а не отчёт о ходе разработки. Разработанные функции должны выполняться, остальные разделы — показывать «В разработке». Основной вход — `current_app.py`; прежний технический просмотрщик сохранён отдельно в `archive_viewer.py`.

## Запуск

Откройте `run_app.bat`. Он запускает приложение из `.venv-app` на локальном адресе, независимо от того, из какой папки вызван. Или из корня проекта:

```powershell
.\.venv-app\Scripts\python.exe -m streamlit run current_app.py --server.address 127.0.0.1
```

Требуется полный `requirements.txt`, включая Streamlit >=1.66. Каталог проекта выбирается в настройках хранения. Оператор может задать `TOURISM_PRODUCT_STORE` до запуска. Если доступен локальный архив пилота, он предлагается по умолчанию; иначе используется `data/analysis`. Архивы не входят в Git: при их отсутствии можно запустить сбор, ручные входные файлы не обязательны.

## Рабочий процесс

1. **Территория.** Введите название и нажмите «Собрать и открыть проект». Действующий CLI E03 получает границу, POI и дорожные линии, проверяет необязательные источники и сохраняет снимки. Можно вместо сбора открыть сохранённую территорию и её версию. Только результат, прошедший проверку манифеста/хэшей, становится текущим проектом.
2. **Каркас территории.** Карта, категории, поиск и выделение POI работают по открытому проекту. В отдельном режиме доступны ID-связи, кандидаты и исключённые пары ЕГРОКН. Карта не требует внешних тайлов/API-ключа; исходные линии не являются рассчитанными маршрутами.
3. **Источники и качество.** Показываются даты, полнота, SHA-256 и причины исключения наборов. «Подключить / обновить каталоги» запускает действующий CLI E04 от исходного запуска сбора, сохраняет дочернюю версию и открывает её. OSM этой кнопкой не обновляется. Доступны экспорт отчёта и JSON-паспорта.

Данные сохраняются автоматически. Переключение страниц само по себе не обращается к источникам и не запускает расчёты. Выбранная территория и версия остаются общими для страниц. Смена хранилища закрывает текущий проект, но не удаляет снимки.

## Какие разделы пока заглушки

| Раздел | Что ещё требуется реализовать |
| --- | --- |
| Территориальные ограничения | Проверенные правовые геометрии, периоды и фильтры действий |
| Доступность | Пригодный режимный граф, входы, пересадки и недостижимость |
| Услуги и дефициты | Совместная доступность; D/K для численного обслуживания |
| Поездки | Бюджет времени, окна, длительности и сервисная цепочка |
| Мероприятия | Обоснования, допустимость, затраты, зависимости и альтернативы |
| Сценарии | Сочетания мер, бюджет, этапность и версии |

В этих разделах показана пометка **«В разработке»**, расчётные кнопки отключены, фиктивные карты, показатели и рекомендации не создаются. Полный E13 не завершён: реализован продуктовый каркас и работа с доступными E03/E04.

## Сбор и ошибки

- Обычный режим разрешает сеть **после нажатия кнопки**. Первый PBF — около 625 МиБ плюс независимая архивная копия. Поддерживаемый охват ограничен существующим поставщиком Северо-Запада, а не всей Россией.
- Флаг «Только проверенный кэш — без сети» передаёт настоящий `--offline`. Просроченный кэш не продлевается ради показа. При отсутствии/истечении кэша будет явный отказ, не успешная пустая территория.
- Частичный статус не равен провалу первичного сбора: необязательная статистика может быть исключена, POI/дороги сохранены. Но это не готовность спроса, правовых условий или рекомендаций.
- При ошибке ранее открытый проект остаётся выбранным. Диагностика — в `logs/product-ui/` выбранного хранилища и штатных журналах конвейера. Одновременно выполняется только одна продуктовая операция на хранилище; чужие lock-файлы не удаляются.
- Операция выполняется синхронно с техническим лимитом 30 минут. Таймаут завершает дочерний CLI; автоматическое восстановление внутренних lock после аварии источника пока не реализовано (E15). Не запускать повторный сбор в другой вкладке, пока операция не закончена.

Старый исследовательский baseline: `app.py`. Техническая инспекция архивов: `archive_viewer.py`. Они не подменяют основной продуктовый интерфейс.
