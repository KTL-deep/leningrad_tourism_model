## Роли наборов и границы вычислимости v1.1

Ниже закрывается планирование контрактов для первого пути E02/E03. Это не заявление, что провайдеры уже подключены. Наборы из разных источников сопоставляются по территории, периоду, единицам, происхождению, полноте и разрешённому использованию. HTTP 200/страница каталога не подтверждает ни одну численную величину.

Политика включения проверяет утверждения адаптера о качестве и доступе, **не заменяет сами проверки**. Для первого консервативного контракта полные численные наборы со статусом complete рассматриваются отдельно от partial/unknown; частичные наборы не превращаются автоматически в полноценные входы. Пространственные данные partial сохраняют ценность для разведки, но выпуск проверенного слоя потребует отдельного правила покрытия E03/E04. Слой правовых данных — лишь необходимый вход: даже его включение не доказывает допустимость конкретного действия.

Эта структурная политика теперь реализована в `src/etl/source_policy.py` и связана со снимками через `src/pipeline/input_assessment.py`. Флаги должны быть настоящими bool, территории/источники не смешиваются; запись HTTP-probe сама по себе не включает набор. Независимые офлайн-тесты подтверждают контракт, но не наличие содержательных адаптеров или полноту реальных источников.

## Реализованный территориальный адаптер — первый срез E03

`src/etl/adapters/nominatim_boundary.py`, версия `nominatim-boundary-v1`. Один явный запрос названия территории, фиксированный протокол Nominatim `/search`, HTTPS без редиректов, идентифицированный User-Agent с URL проекта, таймауты 10/25 с, максимум ответа 2 MiB. Параметры: нормализованный q, format=jsonv2, addressdetails=1, polygon_geojson=1, limit=5, countrycodes=ru, accept-language=ru. Это не перечисление POI и не generic адресный сервис.

Схема данных: список объектов с category/class, type, osm_type/osm_id, display_name, geojson, address.state при наличии. Координаты lon/lat в градусах EPSG:4326; никаких площадей/расстояний в градусах не вычисляется. Полнота complete относится **только к выбранному полигону**, не к инвентаризации ресурсов/правовым границам. Адресная юрисдикция — source_reported.

Источник: OpenStreetMap contributors через публичный Nominatim OSMF. Условия: [Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/), ODbL/атрибуция `© OpenStreetMap contributors (ODbL)`. Авторизация/оплата для проверенных GET не требовались. Кэш обязателен; техническая TTL 24 часа не является сроком действия границы. Запросы одного общего каталога сериализуются с интервалом 1,1 с. Нельзя обходить общий лимит несколькими хранилищами или использовать CLI как bulk/периодический геокодер. Endpoint меняется оператором без правки кода, для нестандартного нужны подтверждённые им условия.

Исходные байты, JSON-метаданные и манифесты сохранены в игнорируемом `data/analysis/`. При чтении кэша проверяются запрос/endpoint/версия, хэш/байты, идентичность и заново построенная геометрия. Неоднозначность, повреждённый кэш, HTTP 403/429, TLS/таймаут и отсутствие поддерживаемого полигона имеют отдельные ошибки. Старый валидный указатель/снимок не стирается при сбое; чужой lock автоматически не удаляется.

### Резерв Geofabrik — 23.10.2026

Повтор Overpass для Гатчины завершился timeout, новая граница сохранена (run `e8759672337a41e9ac4806c985516718`). Публичная [страница региона](https://download.geofabrik.de/russia/northwestern-fed-district.html) и [technical](https://download.geofabrik.de/technical.html) прочитаны: ежедневный OSM PBF Северо-Запада, ODbL, атрибуция OSM contributors/Geofabrik, без логина/пользовательских метаданных. Выгрузка около 625 МБ, меньших подрегионов у поставщика нет. HEAD датированного PBF дал HTTP 200 и длину 655544853; полигон покрытия `.poly` получен и хэширован. Это не означает успешный разбор PBF; фактические результаты — в validation.

Новый отдельный `scripts.collect_osm_extract` проверяет bbox (до 1000 км²) на покрытие `.poly` и сохраняет PBF в собственном проверяемом файловом кэше: SHA-256/размер/URL/дата получения/TTL 24 часа, download limit 768 MiB и 3600 с. Один проверенный 307 с latest на датированный файл того же сервера; TLS обязателен, произвольные редиректы/зеркала не используются. Эксклюзивная блокировка действует в одном каталоге кэша, чужая блокировка не удаляется автоматически.

Локальный разбор osmium использует sparse disk index для глобальных OSM ID, а не dense array/Python-словарь всех узлов. Вывод ограничен 200000 features / 64 MiB / 1800 с разбора. С версии v2 дополнительно поддержаны явно POI-тегированные `type=multipolygon` relations с проверкой всех частей, отверстий и исходных ролей колец; остальные типы relations и нетегированные legacy-relations не поддержаны. Действуют fail-closed лимиты по 200000 отслеживаемых кандидатов, уникальных member ways и ссылок их узлов во всём файле, а также 64 MiB собранного WKB. Это ограниченный региональный срез, **инвентаризация partial**. Невалидная дата базы отвергается, отсутствующая — unknown. Примерные центры ways/relations не являются входами; мощность, фактическое открытие, режимы/расписания и времена движения не выводятся, дубли не разрешены. PBF потоково архивируется в независимый SourceSnapshot и разбирается из архива; исходный снимок, граница и частичные производные экспорты связаны RunManifest. В provenance указан source_snapshot_id; run_manifest_id остаётся null ради идемпотентности экспортов, а идентификатор запуска доступен в выводе CLI. Наблюдения сохраняются как supporting-артефакты, но не включают расчётные возможности: статус оценки входов failed при partial-сборе. Для v1 есть `--node-way-only`; Rust-предотбор v1 не подключён к v2. Ограниченный резерв не означает завершение E03, полноту обследования или готовую маршрутизацию. См. ADR 0008, ADR 0010 и ADR 0011.

24.10 архивный разбор того же PBF (без HTTP/продления TTL) дал **1005 POI, из них 48 relations, и 5568 дорог**; все прежние 957 node/way POI и дорожные записи совпали полностью. Во всём региональном PBF: 3933 подходящих multipolygon-кандидата, 6 несобранных, 14 некорректных, 96 POI-relations других типов. Эти ошибки нельзя приписывать Гатчине без геометрии. У пяти выборочных relations теги сверены с исходным PBF (включая Дворцовый парк и Сильвию); это проверка происхождения, не независимая оценка полноты или точности границ. Отчёт и хэши — в validation.

Ни для одной непроверенной категории отсутствие открытого источника пока не установлено. Целевая схема — бесплатное, независимое от одного источника автоматическое получение из нескольких допустимых источников, а не обязательный PDF каждого города или пользовательский CSV. Официальные показатели посещаемости, населения и другие статистические наборы включаются в численные расчёты **только если** программа сама обнаружила и получила пригодные данные и проверила происхождение, период, единицы, охват и условия использования. Допустим ранее проверенный разрешённый кэш с датой и оценкой качества. Иначе набор исключается, фиксируются unknown и причина; работа продолжается в сокращённом/условном режиме без подстановки нуля. Это целевая политика, не реализованный механизм E01. Не заменять отсутствующую статистику отзывами: число отзывов не означает посещения, спрос или мощность; дата публикации не равна дате визита. `rating_count`, `text_review_count` и размер собранного корпуса различаются; темы отзывов — сообщения об опыте, требующие независимого подтверждения. Обязательные геометрия/сеть и правовые проверки этой политикой не отменяются.

Официальная документация Yandex Organization Search API (https://yandex.ru/maps-api/docs/geosearch-api/response.html) не описывает выдачу текстов отзывов; продукт платный (https://yandex.ru/maps-api/products/geosearch-api). Рабочий API отзывов здесь не установлен. Яндекс, платёж или вход не являются обязательными условиями запуска; обход интерфейсов/ограничений не допускается.

## Продолжение E01 — повторяемые проверки

Пункты выше сохраняют результаты **первого** probe в 07:02 UTC, а не текущее состояние разбора PDF. В следующем шаге добавлены `configs/source_probes.json` (каталог кандидатов с общими полями license/auth/frequency/units и overrides), `scripts/probe_sources.py` и источник-специфичный адаптер PDF. Общие поля со значением unknown — явные пробелы, а не подтверждение отсутствия ограничений.

Команда из корня (выходной файл обязательно новый):

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.probe_sources --output data/audit/source_probes_20261019_e01.json
.\.venv\Scripts\python.exe -X utf8 -m src.etl.adapters.gatchina_report
```

Первый файл уже создан и защищён от перезаписи: для следующей проверки использовать другой timestamp в имени. Скрипт не выполняет JavaScript, не отключает TLS и не повторяет заблокированные запросы. Сохраняется время UTC, HTTP-статус, финальный URL, тип, число прочитанных байтов и их SHA-256; тело ограничено 1 MiB. Хэш при truncated относится только к прочитанному префиксу; хэш пустого тела при сетевой ошибке не является снимком пустого набора. Это **журнал разведки**, не хранилище исходных снимков E02. Сырые тела probe не сохраняются. Повторный probe не использует кэш и не должен запускаться часто; его не использовать для регулярного геокодирования.
