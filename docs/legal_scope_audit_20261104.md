## 2. Простой объём до декабря

Нужен предварительный контроль применимых ограничений для **конкретного действия**. Не нужна экспертная система, понимающая произвольные законы и карты.

Первая версия: один небольшой каталог проверенных правил, пространственное пересечение GeoPandas/Shapely и понятные результаты. На каждой территории программа автоматически пробует только поддерживаемые источники. Неудача не превращается в поручение пользователю загрузить/обвести карту.

Разделить два вопроса:
- **Нужна ли мера по модели?** Это диагностика и условный сценарий.
- **Достаточно ли оснований предлагать её к реализации?** Это проверка конкретных правил и незакрытых условий. Положительный результат нашей проверки не заменяет официальных разрешений.

| Группа | Что делаем в первой версии | Если данных недостаточно |
| --- | --- | --- |
| ПЗЗ / вид использования | Пересечение с подтверждённой зоной и проверка вида действия по явно извлечённому регламенту | Вариант размещения остаётся условным; не выдаём точный участок как допустимый |
| ОКН / охранные режимы | Проверяем полученную официальную территорию/зону и конкретный режим для данной работы | Точка ЕГРОКН не даёт границы; unknown, без универсального радиуса |
| ООПТ | Проверяем доступную официальную границу/зонирование и установленный режим конкретной ООПТ | Не объявляем всю ООПТ запрещённой и не разрешаем работы по отсутствию слоя |
| Вода / иные ЗОУИТ | Применяем полученный действующий контур и относящийся к действию запрет/условие | Флаг проверки; берег OSM и произвольный буфер не становятся юридической зоной |
| Общее пользование / благоустройство | Для мер на улице/в парке проверяем соответствующие акты и доступ/условия работ | Общее пользование не означает свободное размещение объекта; условный вариант |
| Доступность МГН / параметры благоустройства | Указываем необходимую дальнейшую проверку по СП 59/СП 82; проверяем только реально известные параметры | Не называем маршрут безбарьерным по тегу wheelchair или расстоянию |
| Генплан / стратегия / РНГП | Показываем связь с документами и применимые нормы с подтверждённой сферой действия | Не превращаем функциональную зону генплана в разрешённый ВРИ и жительскую норму в спрос туристов |

Ограничить реализацию первым поддерживаемым пространственным форматом и двумя группами, для которых получены пригодные данные. Остальные группы сохраняются обязательными пунктами отчёта с unknown/условиями, а не превращаются в обещание полного автоматического покрытия. Это ограничение полноты метода, которое нужно явно назвать в НИР.

## 3. Результаты проверки вместо слова «разрешено»

| Код | Вывод в отчёте | Поведение |
| --- | --- | --- |
| blocked | Обнаружен подтверждённый запрет именно на это действие | Исключить действие из всех выбираемых пакетов, включая условные; высокая польза запрет не компенсирует |
| requires_review | По известному правилу нужны согласование, разрешение, специальный проект или сведения об условиях | Оставить в исследовательском сценарии с перечислением условий; не выдавать за готовое к реализации |
| unknown | Нет пригодного контура, действующей редакции, точной привязки или понятного применимого правила | Условная зона/гипотеза, без вывода о законности; причина и отсутствующий вход обязательны |
| no_conflict_in_checked_scope | По перечисленным выполненным проверкам противоречий не выявлено | Указать охват и оставшиеся проверки; **не** писать «строительство разрешено» |
| not_applicable | Данная группа не относится к действию, есть обоснование | Исключить только эту проверку; соседние группы не становятся пройденными |

Положительный статус допустим только когда выполнены все **заявленные применимыми** проверки этой меры; неизвестные группы не исключать из списка ради положительного результата. Неполноту территории/источников показывать отдельно. Один блокирующий запрет имеет приоритет; прочие причины/неизвестности тоже сохраняются. Если есть requires_review и unknown, перечислить оба, итог не считать положительным.

Отсутствие пересечения с известными полигонами не доказывает отсутствие ограничений, если покрытие слоя не подтверждено. При приблизительной геометрии предложения нельзя уверенно заключать, что площадка находится вне зоны. Граница касания/пересечения требует определённой в правиле семантики; intersects само по себе не устанавливает запрет.

## 4. Минимальные данные и алгоритм

Не менять существующие SourceSnapshot/Evidence/RunManifest. Производный результат связывается с этими снимками, не редактирует их.

Запись правила: rule_id; document_id; точный пункт/фрагмент; юрисдикция; даты действия; типы мер; геометрия/снимок; явно сформулированное условие; результат; предел применимости; дата проверки. До заполнения пункта/редакции/геометрии шаблон не является действующим запретом.

На входе меры: тип и масштаб работ (новое капитальное / некапитальное / реконструкция / ремонт / использование существующего / информационное), геометрия и её точность, фактическое изменение, связанные объекты и подтверждённые условия. Тип «сервис» без объяснения, что именно строится/меняется, недостаточен. Некапитальность и малый бюджет сами по себе не освобождают от ограничений.

Простой алгоритм:
1. Определить применимые группы проверок по виду меры, территории и дате. Без свободного толкования законов LLM.
2. Получить поддерживаемые официальные документы/слои, проверить происхождение, период и покрытие. Для местных ПЗЗ учитывать основной акт и применимые изменения, включая акты только для части территории.
3. Если это скан/непривязанная PDF-карта без поддерживаемой геометрии — source_unusable/geometry_unavailable, затем unknown. Не создавать универсальный OCR или автоматическую оцифровку к декабрю.
4. Для пригодных слоёв выполнить пространственную проверку, затем простую проверку заранее описанного условия. Наличие зоны без прочитанного режима даёт requires_review/unknown, а не автоматический blocked.
5. Сохранить результаты всех групп и источники. Подтверждённые запреты фильтруются **до** оптимизации; условия/unknown попадают только в явно условную исследовательскую ветку.
6. В оптимизаторе разные флаги: model_feasible и legal_check_status. Математически осуществимый пакет не переименовывать в юридически допустимый. В итоговом отчёте показывать каждую меру и её незакрытые условия.
7. При изменении документов/геометрий проверять зависимые меры заново по новой версии. Не выбирать правовой акт просто потому, что URL самый свежий.
8. Показывать отдельную долю checked/unknown/blocked и перечень непокрытых групп; это показатель полноты проверки, а не качества законодательства или туристической привлекательности.

Подготовленные группы и основания: [configs/legal_check_catalog.json](../configs/legal_check_catalog.json). Это **спецификация**, execution_enabled=false; файл не подключён к runtime и не содержит юридических буферов/исполняемых запретов.

## 5. Что конкретно не делаем в декабрьском методе

| Задача | Почему текущий метод не сможет дать достоверный результат | Что честно выдаём / где продолжение |
| --- | --- | --- |
| Гарантия «здесь можно построить ресторан/гостиницу» | Нет полного набора прав на землю, всех ограничений, проекта и решений уполномоченных органов | Перспективная зона и условия проверки; инвестиционная/проектная стадия вне НИР |
| Автоматическое понимание всех ПЗЗ и сканированных карт пяти городов | Разные документы, изменения, системы координат и графические форматы; универсального адаптера нет | Только поддерживаемые источники; иначе unknown. Расширение — дополнительные адаптеры |
| Полный контроль всех ЗОУИТ/сервитутов/прав собственности | Получение и полнота сведений по каждой площадке не подтверждены; публичная карта не равна исчерпывающей выписке | Перечень непроверенных условий; расширение при подключении пригодных данных |
| Автоматическое получение согласований / разрешения на строительство | Это административные процедуры, не результат пространственного алгоритма | requires_review с основанием; программа не подаёт заявления и не обещает согласование |
| Археологические обследования, воздействие на ОКН и панорамы | Нужны специальные исследования, точные проекты и иногда экспертизы; реестр точек этого не содержит | Не предлагать уверенное вмешательство; проектная стадия/специальное расширение |
| Утверждённая экологическая ёмкость ООПТ | Нет универсального числа из площади/33-ФЗ; нужны специальные данные и применимая методика | Режим/сезонность где подтверждены; пропуск численной нагрузки с причиной |
| Полное соответствие СП: пожарные разрывы, парковки, инсоляция, сети, санитарные условия | Нужны габариты/назначение/класс и проектные данные, отсутствующие в городском POI-анализе | Требование дальнейшей проверки; не выдавать галочку «соответствует всем СП» |
| Подтверждение безбарьерности маршрута | Нет непрерывных проверенных данных о ширине, уклонах, покрытиях, бордюрах, входах и оборудовании | Отдельные наблюдаемые признаки; соответствие СП 59 не подтверждено |
| Новые мосты/дороги, изменение ПЗЗ/генплана | Потребуются проекты, процедуры, инженерные/земельные основания | Стратегическая потребность вне готового портфеля; расширение, не автоматически разрешённая мера |

Это не утверждение о принципиальной невозможности задач. Часть требует других данных/этапов, часть относится к полномочиям органов и не может быть заменена программой. Недостаток сроков не отменяет правовой запрет и не превращает непроверенный вариант в законный.

## 6. Критерии реализации E06 без усложнения

Достаточно: один поддерживаемый реальный слой с актом/датой/геометрией и действием; один проверенный тип запрета; unknown при неподдерживаемом источнике; перечень согласований; передача статуса в отбор и отчёт. Для остальных пятигородских случаев фиксировать реальное покрытие, не требовать фиктивных положительных результатов.

Проверки при реализации: запрет исключён несмотря на пользу; согласование не стало pass; отсутствующий слой не стал пустым; нет правила по точке ОКН вместо территории; частичный акт не распространяется на весь город; дата/смена режима; конфликт геометрий/CRS; только поддерживаемые группы и подсчёт unknown. Малые синтетические случаи — проверка алгоритма, реальная зона с актом — проверка применимости. До этих свидетельств E06 остаётся not_started/partial по фактам, а не done по наличию JSON.

Оценочный лимит первого прототипа — 3–5 рабочих дней после нахождения пригодного слоя. Если слой не получен в пределах заранее установленного бюджета поиска, не тратить декабрь на универсальную оцифровку: зафиксировать блокер, ограничить вывод и продолжить независимую диагностику. Это плановый предел усилий, не измеренная трудоёмкость и не технический timeout сервиса.

## 7. Формулировка для текста НИР

«Метод выполняет предварительную проверку предлагаемых мероприятий по доступным и проверенным градостроительным и территориальным ограничениям. Подтверждённые запреты исключают мероприятие из выбора; необходимость согласований и недостаток сведений отражаются в условиях сценария. Автоматизированная проверка ограничена поддерживаемыми источниками и не заменяет проектирование, правовую экспертизу и административные процедуры. Полнота проверок раскрывается отдельно для каждого примера апробации».

До реализации писать «в методе предусмотрена проверка», а не «программа выполняет». Если в апробации все правовые результаты unknown, это фиксируется как **неапробированная часть** метода; нельзя заявлять подтверждённый учёт реальных ограничений.

Нормативная база с реквизитами, ссылками, применением и пределами проверки — [legal_rules.md](legal_rules.md). Текст выше — собственная формализация автора, не дословное положение закона.
