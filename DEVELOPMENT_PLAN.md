# План разработки

Документ описывает пошаговый план реализации модели выбора территории под туристическую застройку.

---

## 1) Разбиение территории на ячейки (Городские блоки)

**Цель:** получить корректный набор полигонов блоков, покрывающих исследуемую территорию.

**Ключевые задачи:**
- загрузить границу территории и барьеры (дороги, вода, при необходимости ж/д);
- привести данные к метрической CRS (UTM) для корректных расчетов площадей и длин;
- сформировать полигоны блоков алгоритмом нарезки;
- отфильтровать артефакты (слишком узкие/малые полигоны);
- присвоить стабильные идентификаторы блоков (`block_id`).

**Артефакты этапа:**
- `GeoDataFrame`/GeoJSON с блоками;
- базовая проверка топологии (валидность геометрий, отсутствие дубликатов).

**Критерий готовности:**
- территория полностью покрыта блоками, геометрии валидны, блоки готовы к атрибутированию.

---

## 2) Оценка привлекательности (Многокритериальная оценка AHP)

**Цель:** получить интегральный балл привлекательности для каждого блока.

**Ключевые задачи:**
- определить набор критериев (например: культурное наследие, amenities, доступность, тип землепользования);
- собрать/нормализовать показатели по каждому критерию;
- задать матрицу попарных сравнений AHP и вычислить веса;
- проверить согласованность суждений (Consistency Ratio);
- рассчитать итоговый `attractiveness_score` по блокам.

**Артефакты этапа:**
- таблица критериев и весов;
- файл с результатами AHP (веса, CR, промежуточные расчеты);
- обновленные блоки с полем интегрального балла.

**Критерий готовности:**
- у каждого блока есть воспроизводимый и интерпретируемый итоговый балл привлекательности.

---

## 3) Перевод баллов во «вместимость» (Трансформация в BlocksNet)

**Цель:** преобразовать привлекательность блоков в параметр вместимости для сетевой модели.

**Ключевые задачи:**
- выбрать функцию трансформации `score -> capacity` (линейная, логарифмическая, квантильная и т.д.);
- зафиксировать границы и масштабирование (min/max, clipping, нормировка);
- ввести ограничения (минимальная/максимальная вместимость, опционально зависимость от площади);
- подготовить структуру данных для интеграции с BlocksNet.

**Артефакты этапа:**
- спецификация трансформации и ее параметров;
- блоки с полем `capacity`;
- экспорт данных в формат, совместимый с транспортным расчетом.

**Критерий готовности:**
- значения вместимости устойчивы, объяснимы и пригодны для дальнейшего транспортного анализа.

---

## 4) Проверка дорог и расчет дефицита (Транспортный граф)

**Цель:** определить, где текущая дорожная сеть не покрывает ожидаемую нагрузку.

**Ключевые задачи:**
- построить транспортный граф (узлы, ребра, атрибуты времени/длины/пропускной способности);
- привязать блоки к графу (точки входа/выхода, ближайшие узлы);
- смоделировать поток, связанный с вместимостью блоков;
- рассчитать дефицит пропускной способности по участкам графа и/или блокам;
- выделить проблемные зоны с максимальным транспортным риском.

**Артефакты этапа:**
- граф дорожной сети и производные метрики;
- таблица/карта дефицита;
- список узких мест (bottlenecks) для учета в оптимизации.

**Критерий готовности:**
- получена количественная оценка транспортного дефицита и карта приоритетных зон улучшений.

---

## 5) Поиск идеального места для стройки (Имитация отжига)

**Цель:** найти оптимальную локацию (или набор локаций) с учетом привлекательности и транспортных ограничений.

**Ключевые задачи:**
- сформулировать целевую функцию (максимизация эффекта при штрафе за дефицит/риск);
- определить ограничения (запрещенные зоны, бюджет, минимальные расстояния, лимиты по площади);
- задать состояние решения и соседние переходы для алгоритма;
- настроить параметры имитации отжига (начальная температура, schedule, критерий остановки);
- выполнить серию запусков для проверки стабильности найденного решения.

**Артефакты этапа:**
- модуль оптимизации и журнал экспериментов;
- итоговые координаты/блоки кандидатов;
- сравнение лучшего решения с базовыми сценариями.

**Критерий готовности:**
- найдено устойчивое решение, улучшающее целевую функцию относительно базовых вариантов.

---

## Сквозные требования ко всем этапам

- фиксировать входные данные, параметры и seed для воспроизводимости;
- сохранять промежуточные артефакты в `data/processed`;
- документировать принятые допущения и ограничения;
- покрыть ключевые вычислительные функции тестами.
