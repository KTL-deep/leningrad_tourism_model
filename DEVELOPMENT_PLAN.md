# План разработки

Документ описывает пошаговый план реализации модели выбора территории под туристическую застройку.

---

## 1) Генерация пространственных ячеек (Городские блоки)

**Цель:** получить набор полигонов (блоков), выступающих базовыми единицами для классификации территорий.

**Ключевые задачи:**
- загрузить границу территории и физические барьеры (дороги, вода);
- привести данные к метрической CRS (UTM) для расчетов длин и площадей;
- сформировать полигоны (с использованием библиотеки `blocksnet`);
- отфильтровать артефакты геометрии (слишком узкие/мелкие полигоны);
- присвоить стабильные идентификаторы (`block_id`).

**Артефакты этапа:**
- `GeoDataFrame`/GeoJSON со слоем городских блоков;
- базовая проверка валидности геометрий.

**Критерий готовности:**
- территория полностью покрыта ячейками, полигоны готовы к обогащению данными (атрибутированию).

---

## 2) Атрибутирование блоков (Формирование профиля факторов)

**Цель:** собрать, нормализовать и привязать к блокам все семантические данные (факторы), необходимые для классификации типа застройки.

**Ключевые задачи:**
- сопоставить блоки с внешними данными (объекты культурного наследия, сервисы, ООПТ, тип землепользования);
- рассчитать агрегированные значения для полигонов (количество ОКН, доля площади ООПТ, доминирующий тип landuse);
- подготовить и нормализовать показатели для передачи в математическую модель (AHP);
- зафиксировать базовые признаки в таблице атрибутов блока.

**Артефакты этапа:**
- обогащенный слой блоков (UCM), содержащий полный набор факторов для последующего анализа.

**Критерий готовности:**
- у каждого блока сформирован достоверный набор нормализованных признаков (ОКН, сервисы, экология и др.), готовый к расчету сценариев.

---

## 3) Выделение сценариев использования (Определение типов застройки)

**Цель:** определить конкретные типы застройки (парки, детские/спортивные площадки, отели и т.д.) и их требования к территории.

**Ключевые задачи:**
- составить перечень сценариев использования территории;
- с помощью метода Саати (AHP) определить уникальный профиль весов факторов для каждого сценария;
- сформировать матрицу требований: какой тип застройки требует близости к ОКН, какой — к водоемам, а какой к дорогам.

**Артефакты этапа:**
- задокументированный набор весовых коэффициентов для выделенных сценариев.

**Критерий готовности:**
- готов список конкретных типов застройки с рассчитанными весами важности каждого фактора для каждого типа.

---

## 4) Оценка пригодности блоков под каждый сценарий

**Цель:** для каждого городского блока определить максимально подходящий тип использования.

**Ключевые задачи:**
- для каждого блока рассчитать балл пригодности (suitability score) под каждый из заданных сценариев на основе его атрибутов;
- сравнить полученные баллы внутри блока;
- присвоить блоку категорию "наилучшего использования" (сценарий с максимальным баллом);
- сохранить результаты расчетов как атрибуты геометрии блока.

**Артефакты этапа:**
- слой блоков, где каждый блок помимо базовых атрибутов содержит баллы по всем сценариям и итоговый тег `best_use_type`.

**Критерий готовности:**
- у каждого блока определён наивысший потенциал типа застройки и рассчитаны все необходимые баллы.

---

## 5) Генерация интерактивной карты (Визуализация)

**Цель:** предоставить пользователю визуальный инструмент для анализа территории.

**Ключевые задачи:**
- создать интерфейс (ввод/выбор региона), чтобы получать данные по нужной территории;
- отобразить полигоны блоков на интерактивной карте (в браузере);
- раскрасить блоки в соответствии с их `best_use_type` (каждому сценарию — свой цвет);
- добавить всплывающие окна (popup) при клике или наведении, в которых будут вписаны атрибуты блока и обоснование выбора данного типа использования.

**Артефакты этапа:**
- модуль визуализации (или веб-приложение), возвращающий интерактивную карту.

**Критерий готовности:**
- пользователь по заданному региону получает карту, благодаря которой можно сделать предварительный вывод о том, где лучше проектировать определенный тип застройки или благоустройства.

---

## Сквозные требования ко всем этапам

- фиксировать входные данные, параметры и seed для воспроизводимости;
- сохранять промежуточные артефакты в `data/processed`;
- документировать принятые допущения и ограничения;
- покрыть ключевые вычислительные функции тестами.
